# 2026-11-05

## B082A05 EPD：新增 MSH 强制黑白刷新调试命令

背景：同一份驱动在别的墨水屏上能显示彩条，在 B082A05 屏上整屏均匀灰、无任何结构。需要区分「波形表内容错」与「LUT/源数据通路根本没生效」。

改动文件：
- `main/customer/peripherals/display/B082A05_EPD/epd_waveform.c/.h`
  - 删除编译期宏 `EPD_LUT_DEBUG_FORCE`，改为运行时可设置：`epd_wave_force_set(code)` / `epd_wave_force_get()`。
  - `epd_wave_table_fill_lut()`：force_code != 0 时 256 项全部填 `0xFF000000 | code`，忽略 framebuffer 与波形表；另加 `p_current_wave_from == NULL` 保护。
- `main/customer/peripherals/display/B082A05_EPD/B082A05_EPD.c`
  - 抽出 `epd_flush_begin()`（设 total_frames、挂回调、tps_exit_sleep、发第一帧），`LCD_WriteMultiplePixels()` 与调试命令共用。
  - 新增 `epd_flushing` 忙标志 + `epd_flush_wait_idle()`（20s 超时），避免 shell 刷新与 lcd_task 刷新并发破坏 curr_frame/回调链。
  - 新增 MSH：`epd_black`(=code1)、`epd_white`(=code2)、`epd_force <0-3> [frames]`、`epd_normal`(=恢复波形表)。命令内部直接以 mixed_framebuffer + L8 + LUT 发起一次完整刷新（约 8~9s）。
  - 已用 compile_commands.json 里的原始 arm-none-eabi-gcc 参数做 -fsyntax-only 校验通过。

判定逻辑（force 实验）：
- 屏变全黑/全白 → LUT 与 source 数据通路是通的，问题在波形表内容或像素旧状态处理；
- 屏完全不变 → 不是波形问题，是 LUT 未生效 / 时序 / 电源 / 分辨率配置问题。

## 待验证的面板差异（B082A05 vs 其它屏）
- 分辨率仍配成 1920x1440，而面板是 1440(H) x 1920(V)（pitch 0.0868 推算自 spec 自洽）。
- 帧率：40MHz / LDL240 / FDL1440 = 115Hz，spec 要求 85Hz；若改 1440x1920 需把 freq 降到约 30MHz 才是 85Hz。
- 该屏为 16bit(2bit/pixel) source 接口，先前的 opm060da/e0470a01 是 8bit，LDL 公式 HOR>>3 与 HOR>>2 不同。
- `color_mode = LCDC_PIXEL_FORMAT_F2_SWAP`（面板相关，1↔2 码会互换，force 实验仍能看出变化）。
- 波形表仍是 yzc085（另一颗屏）的表，需屏厂提供 B082A05 官方 waveform。
