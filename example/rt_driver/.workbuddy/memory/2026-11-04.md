## rt_driver + B082A05 EPD "只刷第一次、之后画面不动" 分析

- 现象：log 显示每次刷新都完整执行（CopyToMixedGrayBuffer → 32 帧 → ISR Take 855 ticks），但面板只有第一次显示灰色彩条。
- 排查：
  - HAL 层 LUT 每帧经 LayerUpdate 从 RAM memcpy 到 LCDC 寄存器（bf0_hal_lcdc.c:1753），逐帧 LUT 机制正常。
  - drv_lcd.c:1659 每次 draw 重设 XferCpltCallback，无回调递归问题。
  - diff B082A05_EPD.c vs epd_opm060da.c：唯一功能差异 = opm060da 每次刷新前 tps_exit_sleep()、刷新完成 tps_enter_sleep()（电源逐次开关）；B082A05 只在 init 时唤醒一次，电源常开。
  - epd_waveform.c 波形表名为 yzc085_*，是复用其它屏的表。
  - tps_init(2100) → VCOM=-2.1V，超出 spec（-2.0~-1.0V），且注释写"-1.5V"自相矛盾。
- 结论/建议：首要怀疑 TPS65185 电源轨（首次 6.6W 大刷新后掉电/面板要求逐次上断电，spec 第 8 章有完整上下电时序）；修复 = 移植 opm060da 的逐次电源开关模式 + 读 PG(0x0F) 验证；其次验证 B082A05 官方 waveform；纠正 VCOM。
- 次要观察：刷新周期 ~33s，ISR 完成→下一次 Write 之间 ~29s 空档，疑似 8MB PSRAM 帧缓冲逐像素填充极慢（uncached 写）。
- epd_tps.c vs 手册/TPS65185 对比结论：UPSEQ0(VGL→VNEG→VGH→VPOS)、DWNSEQ0(VPOS→VGH→VNEG→VGL)、DWNSEQ1(12/6/24ms) 均满足 spec 上电链 VNEG→VPOS / VGL→VGH 与下电要求（VGL 最后断、VGL<VCOM 衰减）；exit_sleep 50ms+10ms 裕量充足。问题不在时序内容，而在 B082A05 驱动从未逐次调用 enter/exit_sleep。另：DWNSEQ1 误用 TI_UPLY6MS 常量（值=12ms 仍合法）；VCOM=-2.1V 超 spec 范围(-2.0~-1.0V)；未读 PG(0x0F) 校验；Ted 0.5s 放电间隔满足（周期>3s）。TPS65185 下电序列由 PWRUP 下降沿触发（已查证 datasheet）。

## 修复：B082A05 添加逐次电源开关（用户已自行改好 VCOM）

- `epd_tps.c`：`tps_enter_sleep()` 改为纯 GPIO 拉低（删掉 2 个 mdelay(10) 和 printf），因为它会在 LCDC 回调（ISR 上下文）中被调用；下电序列由 TPS65185 内部自动执行，MCU 侧无需延时。与 opm060da 的 tps 实现一致。
- `B082A05_EPD.c`：
  - `LCD_Init`：tps_init 后 exit_sleep → enter_sleep，保证初始为断电状态（否则首次刷新前 PWRUP 已高、无上升沿）；
  - `LCD_WriteMultiplePixels`：发第一帧前调用 `tps_exit_sleep()`（线程上下文，含 mdelay(50)，安全）；
  - `StartFrame` 完成分支调用 `tps_enter_sleep()`（ISR 安全版）。
- 现在每个刷新周期 = 完整 power-up（PWRUP 上升沿触发）→ 32 帧驱动 → power-down，符合面板手册第 8 章 Power Sequence 意图。待用户上板验证。
