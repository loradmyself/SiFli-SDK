## 52 板 QSPI 屏"有背光无图像"排查

- 现象：PIN43 STBYB 已高、CS/CLK 有波形、数据线有活动，背光亮但无图像。
- 判断：不是时钟极性（LCDC SPI 配置 clk_polarity/clk_phase 默认 0/0 = mode0，CS 低有效，与 ST77903 规范一致；
  极性错表现是花屏/错位，不是全黑）。
- 优先怀疑：面板电荷泵 VSP/VSN/VGH/VGL（U8 pin3/6/7/8，VGH≈+15V、VGL≈-10V、VSP/VSN≈±5V）、
  IOVCC/VCI 是否 3.3V、面板端 RESET/STBYB 实际电平、面板是否要求显式 0x11+0x29。
- 已在 st77903.c LCD_Init 末尾加两个默认关闭的调试宏：
  `LCD_ST77903_SEND_DISP_ON`（补 0x11 sleep-out + 120ms + 0x29 display-on）、
  `LCD_ST77903_BIST_TEST`（面板内部彩条 BIST，5s，用于区分面板/电源问题 vs 视频流格式问题）。
  两配置 -fsyntax-only 均通过。


## 关键发现：st77903 驱动 LCD_Init 现在不发任何初始化命令

- 实际烧的是 `build_sf32lb52-lcd_a128r16_hcpu`（LCD_HOR_RES_MAX=480 / VER=272），不是 n16r8（512x300）。
- `st77903.c` 当前状态：259-266 行 `lcd_init_cmds[]` 发送循环被注释、302-324 行
  `0x00~0x04/0x80/0x84~0x89/0x3a` 写入被注释、281 行 BIST 是 `#if 0`
  → LCD_Init 里对面板的写命令数为 0，屏必然黑。
- `LCD_ReadID()`（347-356）无条件 `return THE_LCD_ID(0x85)`；`LCD_ReadData()`（513-524）
  函数体全注释、直接 return 0。所以日志里 `ST77903_ReadID 0x0` 是空函数返回值，
  `Found lcd st77903 id:85h` 是硬编码常量，不能作为"识屏成功"依据。
- 日志 tick 从 3663 跳到 16111（12.4s），PC 时间只走 196ms，两者矛盾，待实测确认。
- 分辨率：lcd_horizonal_res 来自 `LCD_HOR_RES_MAX`（LCD_DRIVER_EXPORT2），
  `HAL_LCDC_SetROIArea` 与 main.c 的 FB 尺寸都跟它走，改分辨率只需改 rtconfig。

## rt_driver 例程在 57GY 上死机分析

- 现象：启动后 LCD 刷第一帧时断言失败 `bf0_hal_lcdc_aux.c:23`，lcd_task fatal。
- 根因：烧的是 `build_sf32lb57-lcd_n16r16_qspi_hcpu`（LCD_USING_ST77903 + BSP_USING_RAMLESS_LCD）。
  ST77903 驱动接口为 `LCDC_INTF_SPI_DCX_4DATA_AUX`，第一帧 flush 时走 `RAMLESS_FSM_START`
  → `SPI_AUX_HW_FSM_START()`（bf0_hal_lcdc_aux.c:21）。
  该文件在 `#ifdef SF32LB57X` 分支里只实现了 DPI_HW_FSM_*，SPI AUX 系列（START/STOP/RST/READ/WRITE）
  全是 `HAL_ASSERT(0)` 占位桩 —— 即当前 SDK 版本在 57X 上未实现 SPI-AUX(QSPI) 无 RAM 屏的硬件自动刷新 FSM。
- 触发链：main.c lcd_refresh_task → draw_rect_async → HAL_LCDC_RAMLESS_FSM_START → 断言桩。
- 修复方向：改用 DPI 目标（57GY HDK 官方配的是 `dpi-hdk_lb57gyd7n6_epd_hcpu`，DPI 接口在 57X 有完整实现）；
  或升级 SDK 看新版是否补了 57X SPI AUX 实现；不建议自己写 PTM 码实现。
