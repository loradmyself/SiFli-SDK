## 触摸无反应根因：报告描述符 X/Y 挂错 usage page（Digitizer 而非 Generic Desktop）
- 排查链：设备端统计固件证明 EP3 发送全通（tx_ok 涨、无 err）→ hidusb→hidclass 读报告正常
  （直接 ReadFile 拿到 8 字节正确报告）→ Raw Input 设备表无 VID_303A（GetRawInputDeviceList 23 个无我们）→
  SM_MAXIMUMTOUCHES=0、GetPointerDevices=0 → Windows 不认集合为功能触摸屏。
- 乌龙提醒：HIDP_CAPS 字段顺序是 Usage 在前、UsagePage 在后（hidpi.h 实测确认），
  别把 0x0004/0x000D 误读成 usage page 错误。
- 真根因：touch_report_desc 从头到尾没切 usage page，X/Y(0x30/0x31) 在 Digitizer 页下被解析成
  Tip Pressure/Barrel Pressure。微软触摸屏规范强制 X/Y 挂 Generic Desktop(0x01) 页
  （learn.microsoft.com touchscreen-required-hid-top-level-collections 示例有 05 01）。
- 修复：Finger 集合 X/Y 前加 05 01（Generic Desktop），之后恢复 05 0D。编译通过（scons_build4.log）。
- 调试工具链（总线级）：Hub IOCTL 抓描述符脚本 F:\SiFli\usb_sniff2.py
  （IOCTL_USB_GET_NODE_INFO=0x220408 / GET_DESCRIPTOR=0x220410 / CONN_NAME=0x220414 /
  CONN_INFO_EX=0x220448；GET_DESCRIPTOR 的 wValue 高字节=描述符类型；NodeConnectionInformation_EX
  的 ConnectionStatus 在偏移 28；外部 hub 名需加 \\.\ 前缀）。hub IOCTL 发 interface 类请求走
  usbccgp 转发会 err=31，只能拿 config 描述符，report 描述符拿不到。
- HID 调试脚本：F:\SiFli\hid_caps2.py（HIDP caps）、hid_read_test.py（直接读报告）、
  rawinput_probe.py/rawinput_enum.py（Raw Input 监听/枚举）。

## 「configured 但零推流」根因：MUSB 端点方向冲突（EP2 OUT vs EP2 IN）
- 排查链：GDI 枚举确认 DISPLAY54 (2560,0)-(3584,600) 1024x600 是活动桌面 → IddCx ETW
  （provider Microsoft-Windows-IndirectDisplays-ClassExtension-Events，logman 抓 etl）

  TOUCH_IN_EP 0x82 与 DISPLAY_OUT_EP 0x02 撞 EP2，触摸后注册把显示接收端点切成 TX → PC 写永远 NAK。
- 修复：TOUCH_IN_EP 0x82→0x83（EP3 IN，CONFIG_USB_MUSB_EP_NUM=8）。重新编译通过。

  用 PowerShell Set-ItemProperty 写注册表；DLL debug_level 注册表键
  HKLM\SYSTEM\CurrentControlSet\Services\xfz1986_usb_graphic\Parameters\debug_level（已设 5）。
- dxdiag 对 display-only 适配器的监视器信息会张冠李戴（混入 DELL EDID），拓扑以 GDI/CCD 枚举为准。

## 触摸映射到错误屏幕（跟主屏走）根因与修复 —— MultiDigiMon 机制
- 现象：触摸有反应了，但手指在 3 号屏（虚拟屏），指针出现在 1 号屏（主屏）；把虚拟屏设为主屏后触摸就"生效"了
  → 说明 Windows 从未把该触摸数字化仪绑定到任何显示器，走默认规则（未映射 = 主屏）。
- 桌面实际布局（GDI）：DISPLAY1(0,0) 1707x1067 primary=内屏 CSO1615；DISPLAY2(-1920,0) 1920x1080=SAM100E；
  DISPLAY59(2560,0) 1024x600=虚拟屏，其 monitor 设备为 `\\?\DISPLAY#DELD0E6#8&36fc2b84&2&UID256`
  （DELD0E6 是 Dell S2719DGF 的 EDID 记录，被 IddCx 虚拟屏复用 → dxdiag 里看到 Dell 不是错乱）。
- 无效尝试：①直接改 Enum 键 ContainerID 让触摸与虚拟屏同容器 → PnP 重新枚举时被系统覆盖回 {25B2A4C6}；
  ②写 Digimon 但键名不带前缀 → 不生效。
- 正确机制（复刻 MultiDigiMon.exe）：注册表 `HKLM\SOFTWARE\Microsoft\Wisp\Pen\Digimon`
  - 值名 = **"20-" + 触摸设备接口路径**（Raw Input 的 RIDI_DEVICENAME，小写 hid#...）
  - 值 = 显示器设备接口路径（EnumDisplayDevices + EDD_GET_DEVICE_INTERFACE_NAME）
  - 立即生效：user32 私有导出 **ordinal 2532 = NtUserSetDisplayMapping(HANDLE touchDev, HMONITOR)**
    （GetProcAddress + WINFUNCTYPE(HANDLE,HANDLE)，返回 1 成功），无需重启。
- 落地工具：`tools/touch_map.py`（先列表，`python touch_map.py apply` 自动挑非主屏中面积最小的那块绑定，
  `--reg-only` 只写注册表）。实测返回成功，注册表写入 `20-\?\HID#VID_303A...` = `\?\DISPLAY#DELD0E6...`。
- 待验证：指针是否落到 3 号屏、方向/边角是否准确（不准再调 TOUCH_SWAP_XY / MIRROR_X / MIRROR_Y）。
